# v0.1.0 — Daily-Driver Parity Implementation Plan

> **Target:** Nailong Planner **v0.1.0 — the first release, still in development and not yet shipped.** This plan is the remaining scope for that release, not a follow-up version.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Nailong Planner feel like Google Calendar for the daily loops — capture, retrieve, navigate, inspect, and recover — without changing the Canvas visual system or the data model beyond one preferences table.

**Architecture:** Three layers, in dependency order. Layer 1 adds a per-user preferences row and threads it from the server layout into the client calendar. Layer 2 replaces the invalidation-only mutation path with optimistic cache updates plus a session undo stack, so quick-create, details, drags and deletes feel instant and safe. Layer 3 adds the four GCal-shaped surfaces (details popover, quick-create, search, mini-month) and the keyboard/shortcut/mobile layer that ties them together. Every layer leaves the app shippable on its own.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, Tailwind CSS 4 (Canvas tokens in `app/globals.css`), Drizzle + SQLite (`better-sqlite3`), TanStack Query 5, Radix primitives (dialog, dropdown, checkbox already present; **popover** is installed but unused), sonner, FullCalendar 7.1.3, Vitest, Playwright.

**Spec:** [`docs/superpowers/specs/2026-10-21-calendar-ux-parity-design.md`](../specs/2026-10-21-calendar-ux-parity-design.md) — read §3.2 (friction inventory), §6 (decisions D2–D9, D12), §7.2–§7.8 (target interaction model) before starting. The evidence for every gap is in §3 and the audit appendix references.

## Global Constraints

- **No new runtime dependency in v0.1.0.** Use `@radix-ui/react-popover` (already installed, currently unused) for anchored surfaces and sonner's `action` option for undo. Do not add a date library, a command-palette package, or an icon set.
- **Canvas visual layer is frozen.** Radii, Lato, colour tokens, control heights and the existing `components/ui/*` primitives are not redesigned. Two new primitives may be added under `components/ui/` only if they are composed from existing tokens. `tests/e2e/design-tokens.spec.ts` and `tests/e2e/calendar-style.spec.ts` must keep passing **unchanged**.
- **The viewport contract is frozen.** `tests/e2e/viewport-fit.spec.ts` (11 tests) must keep passing unchanged after every task: no page scroll, whole month visible, week view scrolls inside the panel. New chrome must fit *inside* the existing 72 px breadcrumb bar, the sidebar's scroll area, or as an overlay (`position: fixed`, popover, dialog). No new full-width rows above the grid.
- **Accessible names the suite depends on are frozen** unless a step says otherwise: buttons `New event`, `Edit`, `Delete`, `Save`, `Cancel`, `Today`, `Previous`, `Next`, `Open calendars`, `Close`, `Add sub-calendar`, `Calendar settings`, `Options for <name>`, `This event`, `All events`; view labels `Month`/`Week`/`Day`/`List`; dialog label `Calendars`; labels `Title`, `Calendar`, `Repeat`, `Location`, `Notes`, `Email`, `Password`. When an interaction deliberately changes, update the spec **and** the assertion in the same task.
- **Time format:** 24-hour remains the default; 12-hour is per-user preference. Everything that renders a time goes through `lib/time/format.ts` after Task 2 — no new `split("T")[1]`, no new `hour12: false` outside the formatter.
- **Preferences live in the database** (per user, one lazy row). Only the *last used view per device* stays in `localStorage` (key `nailong.lastView.<userId>`), because it is a device preference by design (spec D4).
- **Undo window:** 10 s toast with an `Undo` action, **`z`** (Google Calendar's shortcut) **and** `Ctrl/Cmd+Z` for the last mutation of the session. Confirmation dialogs remain only for deleting a calendar, deleting a whole recurring series, and rolling back an import (later release).
- **No confirmation for deleting a single event**; the delete is optimistic and undoable. If the server rejects the delete, restore the row and toast the error.
- **All new interactive UI is keyboard-operable and focus-visible.** No hover-only affordances; no keyboard-only functionality (every shortcut has a visible control).
- **Mobile:** default view is agenda/List on `<768px` when the preference is `auto`; a floating `+ Event` exists on `<768px`; overlays respect `env(safe-area-inset-*)`.
- **Tests:** every task updates or adds the tests named in its Files block. Run the targeted tests per step, and `npm run lint && npm run typecheck && npm test` before each commit. Do not loosen assertions; update them when behaviour is deliberately changed.
- **Commits:** conventional commits, one per task (`feat(prefs): ...`, `feat(calendar): ...`). Do not commit at step granularity unless a step says so.

## Review Focus

The failure modes this spec implies but no current test exercises. Each line names the task whose tests must pin it.

1. **Typing `c`, `/`, `?` or `j/k` inside a text field must not trigger a shortcut.** The shortcut layer must ignore `input`, `textarea`, `select`, `contenteditable`, and any modified key. Typing a title "Call car repair?" must not open search or help. → Task 7.
2. **Search result outside the loaded range.** Selecting a result from three months ago must change the grid's date *and* open that event's details; a search that only lists text is a dead end. → Task 6.
3. **Undo after the toast has disappeared.** The 10 s toast expires, but `z` (Google's shortcut) or `Ctrl/Cmd+Z` within the session still restores the deleted event (or the pre-drag time). → Task 3.
4. **Complex RRULE survives a dialog round-trip.** Open an event whose rule is `FREQ=WEEKLY;BYDAY=TU;INTERVAL=2`, change only the title, save: the stored rule must be byte-identical. Changing only the calendar or notes must not touch the rule either. → Task 5.
5. **Read-only calendars stay read-only in the new surfaces.** A quick-create must not offer a view-only calendar, a details popover on a view-only event must show no Edit/Delete/Duplicate actions, and a dropped drag into a view-only calendar must be refused server-side with the block reverting. → Tasks 4 and 5.

- [ ] **Step 3: Implement the cache helpers and rewrite the mutation hooks**

`useEvents` keeps its existing key shape `["events", from, to]` (do not change it; the undo tests and search rely on the same cache). Implement `onMutate` pattern:

```ts
onMutate: async (input) => {
  await queryClient.cancelQueries({ queryKey: ["events"] });
  const snapshots = queryClient.getQueriesData<EventView[]>({ queryKey: ["events"] });
  const temp = { ...optimisticEvent(input), id: `temp-${crypto.randomUUID()}` };
  queryClient.setQueriesData<EventView[]>({ queryKey: ["events"] }, (old) =>
    old ? [...old, temp] : old,
  );
  return { snapshots };
},
onError: (_err, _input, ctx) => {
  for (const [key, data] of ctx?.snapshots ?? []) queryClient.setQueryData(key, data);
},
onSettled: () => queryClient.invalidateQueries({ queryKey: ["events"] }),
```

- **GCal-verified behaviours this plan follows:** `c` and the Create/`+ Event` button open the full editor while slot click/drag and `Shift+C` open quick-create; `z` is the undo shortcut (Ctrl/Cmd+Z kept as an alias); `j`/`n` next and `k`/`p` previous; `g` opens the date picker; week/day snap to 15 minutes with a 60-minute create default; deletions are undoable and styled as destructive. **Deliberate deviations:** shortcuts are on by default (GCal ships them off — open decision O8); search ships without GCal's What/Who/Where filters and with a 50-result cap (GCal caps at 200); duplicate is a delight borrowed from Fantastical, not a GCal parity item; the `+N more` popover keeps FullCalendar's content (titles) for v0.1.0; month day click defaults to a timed event rather than the current all-day checkbox; density presets, per-event colours, third time zone, year view and dark mode are deferred to v0.5.0.
- **Known limitation accepted in v0.1.0:** no 30-day trash/restore (the UX research recommends it); the undo stack is session-only. This is recorded in the spec roadmap as a v0.2.0 candidate ("Recently deleted") because it needs a tombstone column and a purge job.
